## TL;DR

- **单一入口**：我只跟总管 YOYO 对话，它拆任务、派给 4 个专职 Bot、收回结果再汇报
- **职责卡**：每个 Bot 写明「只干什么 / 不干什么 / 交付标准」，见 [`bots/`](bots/)
- **Bot 之间直接同步**，人不当传话筒；新建、发信、删除、付费、对外发布由我拍板
- **一个能复用的技能**：[Bot 圆桌会](skills/bot-roundtable.md)，两个 Bot 分立场作答，总管裁决
- 所有过程如实记录，包括踩过的坑

## 效果：一次真实的「Bot 圆桌会」

> 问题：试用期结束后，要不要为 Grok Bot 付费？

| 角色 | 输出 |
|---|---|
| 🎮 玩法教练（价值方） | 付费的独有价值：多 Bot 长期记忆 + 互相派活、持久云电脑能装命令行工具、定时任务 + 专属邮箱让 Bot 离线干活。只聊天的话，普通聊天订阅就够了 |
| 🔬 研究猿（事实方） | 官方没公布各档具体额度；按周给、每周重置；可以设按量付费月上限；定价页只写了信用卡/借记卡；取消政策没写明 |
| 🧭 总管（裁决） | **现在不付费，用满试用期，看数据再定**。第 6 天自动复盘 |

付费的 3 个信号：① 至少 1 个定时任务的结果我每天真的会看；② Bot 直接派活，至少省掉 3 次手动转发；③ 每天额度用量在 10% 左右以内。真要付费，先买最低档月付，按量付费上限设 $0。

## 设计原则

1. **单一入口**：Bot 一多，人记不住谁负责什么，所以只跟总管说话。
2. **职责卡**：派活不用猜，Bot 之间不抢活。
3. **Bot 直接同步**：Bot 之间直接发消息，做完由总管统一汇报。
4. **交付物落盘**：长内容存成文件，对话里只放结论和链接。
5. **人在关键节点拍板**：新建 Bot、发信、删除、付费、对外发布都要先经我同意。
6. **省额度**（试用额度按实际工作量计费）：定时任务每天不超过 2 次，能用事件触发就不轮询；能走命令行就不开浏览器；派活一次说清，结果一次收回。来源：[Grok Bot 套餐说明](https://prod.cursor.com/help/grok-bot/plans) · [Grok Bot Wiki：每周额度](https://www.grokbotwiki.com/guides/grok-bot-weekly-usage-limit)

## 想自己搭一套？

1. 先建一个总管 Bot，让它当你唯一的入口
2. 照 [`bots/`](bots/) 的格式给每个新 Bot 写职责卡：只干什么、不干什么、交付标准
3. 只在需要并行、需要隔离上下文时才开新 Bot，其余用技能补（如 [`skills/bot-roundtable.md`](skills/bot-roundtable.md)）
4. 定好人工拍板的边界，写进总管的规则

## 实践记录（Day 1）

### 1. Bot 圆桌会 —— 试用到期要不要付费？

让两个 Bot 站在不同立场独立作答，总管裁决：

- **玩法教练（价值方）**：付费的独有价值是多 Bot 长期记忆 + 互相派活、持久云电脑能装命令行工具、定时任务 + 专属邮箱让 Bot 离线干活。如果只是聊天，普通聊天订阅就够了。
- **研究猿（事实方）**：官方未公布各档具体额度；按周给、每周重置；可以设按量付费月上限；定价页只写了信用卡/借记卡；取消政策未写明。
- **总管裁决**：**现在不付费，用满试用期，看数据再定。** 付费的 3 个信号：
  1. 至少 1 个定时任务的结果，我每天真的会看
  2. Bot 之间直接派活，至少替我省掉 3 次手动转发
  3. 每天额度用量在 10% 左右以内

  第 6 天自动复盘；若付费，先买最低档月付，按量付费上限设 $0。

👉 这套流程已沉淀成可复用技能：[`skills/bot-roundtable.md`](skills/bot-roundtable.md)

### 2. 从浏览器受限到命令行绕行

云电脑上的浏览器网络通道时好时坏，B 站、YouTube、GitHub 全都打不开。但命令行一直正常，于是：

- 用命令行抓取 GitHub Trending，挑出当天的 AI 相关项目
- 写一段 Python 脚本把数据画成图表
- 结果照样交付，而不是一句"做不了"

**收获**：给 Agent 留一条不依赖 GUI 的备用路线，可靠性高很多，还更省额度。

### 3. 参考社区玩法，再做减法

研读了 [@Jackywxsz](https://x.com/Jackywxsz/status/2108808842045956343) 开源的 12 个 Bot"内容军团"。它是为自媒体生产设计的，我没有照搬：

- 总控岗：我的 YOYO 已经在做
- 资讯岗：和 AI 侦察员重复
- 只取 **研究猿** 和 **学习官** 两个岗位，按公开职责介绍自己重建

再结合 [@qzcanoe](https://x.com/qzcanoe/status/2108836178673959249) 的观点「**少开 Bot，多装技能**」：只有需要并行、需要隔离上下文时才开新 Bot，其余用 Skill 补。所以"圆桌会"做成了技能，而不是又一个 Bot。

### 4. 踩坑记录

| 坑 | 怎么处理 |
|---|---|
| 小红书、闲鱼、B 站搜索会触发风控 | 改用公开榜单、官方 API 或命令行，不硬刚 |
| X 官方 API 部分能力需付费 | 只用可用的公开数据接口，读不到正文就如实说明 |
| 浏览器网络通道不稳定 | 命令行优先；浏览器检测从每小时 2 次降到每天 2 次 |
| 总管**自作主张**做了一个我不需要的每日资讯网站 | 停掉定时任务、下线仓库，并定下规则：**新建任何东西前先问我** |
